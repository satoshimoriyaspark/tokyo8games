# 全10区間・結果画面・大会演出（Preview）

## 遊び方

タイトル → コース・たすき・難易度をえらぶ → 区間 / 往路 / 復路 / 総合 → 設定を決定 → はじめる。

- 区間：全10区間から1区間を選ぶ。約2〜4分。
- 往路：1〜5区。復路：6〜10区。総合：1〜10区。
- 各区間に新しい選手が走る。たすき色と難易度を固定し、スタミナ・脚の負担はリセット。
- 同じ左右交互タップ、風よけ、10秒スパート、EASY/NORMAL/HARDを使用。
- 連続レースは前区間までの累積タイム差で時差スタート。プレイヤーの出発時点を0秒とし、先行CPUは既に進み、後続CPUは差の秒数だけ中継所で待つ。風よけ対象に未出発チームは含めない。
- 6区も累積差を引き継ぐゲーム用ルール。現実の繰り上げ出発、出場資格等は実装しない。

## 記録・結果

- 区間結果：毎区間の完走後。区間賞、個人チームの順位・記録・トップ差、20チームの順位表。
- 往路結果：5区後。1〜5区の合計。
- 復路結果：10区後。6〜10区だけの合計。
- 総合結果：総合モードの10区後。全10区間の合計。
- 後続CPUも同じ走行処理でゴールまで計算する。順位・タイムをランダムには作らない。
- 区間タイムは各チームの実出発から到着まで。1/100秒へ丸めて記録し、合計も整数の1/100秒単位で加算。同タイムは同順位・区間賞を共有。
- 結果は既存ランナー素材を使った静止画。1位は表彰台、その他は仲間と完走。セリフ3種を完走時に選び、保存した結果を開き直しても変えない。
- 区間→往路 / 区間→復路→総合の順に進み、タブで戻って確認できる。
- 次の区間へ進むと短いたすき渡し。スキップ可。動きを減らす設定では静止画＋手動で次へ。

## 途中保存

- localStorage の専用キー `tokyo8games.ekiden.relay.v1` にリレー1件を保存。
- 保存タイミング：新規開始、区間結果、次区間への移動。走行途中のフレームは保存しない。
- タイトルの「つづきから」で区間開始または保存した結果画面に戻る。
- 同じブラウザ・同じPreview URLで再開。別端末への同期はない。
- 既存の保存がある状態で新しいリレーを始めると、上書き前にゲーム内で確認する。
- 破損した保存は読み込まず、保存拒否時は画面で明示する。既存ゲームのキーは一切操作しない。

## 演出と範囲

- 白バイ：実際の先頭より前。先頭集団に近いと画面に入る。
- 中継車：道路奥を定期的に通過。ランナーより先に描画。
- 沿道の観客：旗と腕の小さな動き、応援の吹き出し。スタート・中継所・ゴール付近は多め。
- 街、湘南海岸、山林、芦ノ湖、最終市街地をCanvasのドット絵で描画。既存PNG・公式ロゴは変更しない。
- 本番、main、ルーティング、DNS、保護設定、ランキング、他ゲームは対象外。

## 検証

Node.js + `@napi-rs/canvas` で `node ekiden/tests/relay.cjs`。
VM内のゲーム本体と実Canvasを使用し、全10区間単独・往路5区間・復路5区間・総合10区間を完走。
20チームの確定タイム、区間と総合の集計分離、時差引き継ぎ、結果から再開、区間開始から再開、上書き確認、破損・保存拒否、同タイム順位を確認。
NORMAL・0.3秒交互入力・スパートなしの総合サンプルは約25分。難易度・操作で変動する。
ブラウザでの確認結果は作業報告に記載。iPhone実機の動作や音声はこの自動検証には含まない。
